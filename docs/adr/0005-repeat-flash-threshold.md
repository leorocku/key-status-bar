# 重复闪烁：2 连重复 down 门槛，且不加撤销计时器

状态条新增"重复闪烁"：主机侧自动重复进行中（编辑器连吐字符）时该键块高亮闪烁。钩子层唯一可观测的重复信号是"键已按下又收到 down"（`WH_KEYBOARD_LL` 不提供 repeat-count 与 previous-key-state 位，见 Microsoft Learn WM_KEYDOWN 文档），但该信号也会被信号解析错误的单个杂散 down 触发。

决定一：连续 2 个重复 down 才点亮闪烁（第 1 个只计数）。typematic 约 30Hz，点亮仅延迟约 33ms（无感），换来对单个杂散 down 的完全免疫——杂散 down 不会凑成连续两个，计数随 key-up 归零。

决定二：不加"停止重复就灭灯"的撤销计时器，闪烁生命周期 = 键块生命周期。win32k 的 typematic 一旦启动即自维持：只要主机状态表里键仍按下，重复流不会停，直到 up 到达。因此"重复流停止但键仍按下"在真实场景不发生；若加计时器，反而会在主机确实在重复时灭灯，违反状态条"展示主机侧真相"的契约。残留态（幻影重放骤停但无 up）下 win32k 仍在 typematic，持续闪烁是正确显示。

已拒绝的替代方案：(1) 第 1 个重复 down 即点亮——杂散 down 导致整段按住期间误闪，且无计时器可撤销；(2) 节奏门槛区分 typematic 与幻影心跳重放（~2Hz）——Windows 最慢重复速率 2.5Hz 与幻影 500ms 心跳边界模糊，启发式误判面大于收益，且状态条契约本就包含幻影重放这类链路故障。
